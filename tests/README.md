# Tests

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q          # 32 assertions, about a second
```

Three layers, and the first one earns the most for the least code.

**`golden/`** — `example/` regenerates its four outputs byte for byte. Nothing in that
pipeline reads a clock, so the comparison needs no time faking at all: any silent change
to a number, a page or the icon shows up here. `cases/001` is a fixture too, but only for
`measure.py` — it carries its own copies of the scripts on purpose, and its icon and
verification page were generated by older versions, so they are historical artefacts of
the case rather than of the skill.

**`unit/`** — the gates. Every test here is a CHANGELOG entry, which is to say a
regression that has already happened once: a coverage failure that printed the
percentages and exited zero, a stale `.sig` surviving a failed sealing, a passphrase
prompt with no terminal to answer it, a page that iterated a string character by
character. The seal tests are entirely offline: the TSA is a closed port and `ots` is
kept off `PATH`.

**`repo/`** — invariants that guard silent failures. The worked example must not fork
from the skill. Every flag named in the documentation must exist — `--full-root` was
documented for weeks and exits with an argparse error. And `.gitattributes` must pin the
line endings, because that absence turns a Windows checkout into a false accusation of
forgery: the chain check still says `chain intact` while the signature no longer verifies.

## How the scripts are run

Never imported. They are not a package and never will be — a case folder carries its own
copies, which is what keeps it verifiable after the skill changes. The `workspace`
fixture copies a fixture folder plus today's skill scripts into a temp directory, and
everything runs as a subprocess with `cwd` set there and **no stdin**: a script that asks
for a passphrase with no terminal to ask on hangs, and a hanging test is worse than a
failing one.
